결재 결과 수신(Kafka)과 별개로 "승인되면 무엇을 바꾸나"를 먼저 만든다. ⑤까지 만들면 Kafka 리스너는 ⑤만 호출하면 된다.

- [ ] ① 계산기: 승인된 초과근무 구간을 받아 초과근로를 승인·미승인으로 분리 (`WorkTimeCalculator`, 현재 `approvedOtMin`은 항상 0)
- [ ] ② 재계산 시 그날 승인된 초과근무 신청의 시간을 계산기에 넘김
- [ ] ③ 휴일 판정(`isHoliday`)에 승인된 휴일대체 반영: 근무한 휴일 → 근무일, 대체일 → 휴일, 두 날짜 재계산
- [ ] ④ 근무시간 수정 적용: 신청 항목대로 로그 추가·수정·삭제 (출처 `APPROVAL`, 작성자는 신청자) 후 재계산
- [ ] ⑤ 결재 결과 반영 진입점 `applyApprovalResult(신청ID, 결과)`: PENDING일 때만 승인·반려·회수, 승인이면 ②~④ 실행

**정할 것**
- 초과근무 승인 기준: **신청한 시간 구간 안의 초과근로만 승인(추천)** / 신청한 분량만큼 승인
- 근무시간 수정 승인 시 대상 로그가 그사이 바뀐 경우: **그 항목만 건너뛰고 경고 로그(추천)** / 전부 적용 안 함

**참고**
- 초과근무 승인은 급여에 영향 없음 (급여는 승인 여부와 관계없이 실제 근로시간으로 지급)
- 휴일대체 승인은 급여에 영향 있음 (근무한 휴일의 휴일근로가 일반 근로로 바뀜)

### [근태] 관리자 근태 현황 (티켓 2, 보류)
브랜치 `feat/attendance-admin-status`

- [x] user-service 사원 목록 클라이언트 (`UserClient`, 토큰 전달)
- [ ] 조회 범위 판단 ← **직책 이름 목록·`/duties` API 확정 대기**
- [ ] 일자별 현황 `GET /admin/daily` (이상 집계 + 사원별 목록)
- [ ] 기간별 통계 `GET /admin/period` (최대 92일)
- [ ] 엑셀 다운로드 `GET /admin/export` (선택)

**확정된 내용**
- 응답: 일자별은 상단 집계(대상·출근·미출근·휴일·근태이상 유형별) + 사원별 목록, 기간별은 사원별 합계 + 전체 합계
- `empStatus`를 생략하면 재직자만. 명세의 `ON_LEAVED`는 user-service 값인 `ON_LEAVE`로 고쳐야 함
- 미래 날짜는 400 (전원이 미출근으로 잡히므로)

**권한 (팀 결정)**
- 토큰의 role(USER/ADMIN)은 쓰지 않는다
- 팀장급 이상 직책이 자기 부서원 전부(본인·동급 포함)를 본다. 다른 부서 요청은 403
- 팀장급 판단은 user-service `GET /api/v1/duties/{dutyId}`의 직책 이름으로 (설정 파일에 ID를 두지 않음)
- 전사 조회는 대표급 직책. 인사팀 전사 조회는 부서명 조회 API가 생기면 추가
- 판단은 일자별·기간별·엑셀이 공유하는 한 곳에 둔다

> user-service에 부서명 조회 API가 없어 부서는 ID로만 응답
