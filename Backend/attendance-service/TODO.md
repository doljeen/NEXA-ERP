- [ ] **연도별 공휴일 등록 방식** : 마이그레이션 / 관리자 API / 공공데이터 API 중 결정 (현재 2027년까지 등록)

## 3. 다른 서비스·팀 결정이 필요한 것

| 작업 | 필요한 것 |
|---|---|
| 결재 결과 수신 (신청서 상태 반영 + 승인 내용 적용) | 로컬 Kafka 호스트 포트, 반려 후 재기안 정책 |
| 신청서 회수 `POST /me/requests/{id}/cancel` (선택) | 결재 취소 연동 방식 (결정 문서 D3) |
| 휴가 승인·취소 수신, 휴가 중 출근(`WORK_ON_LEAVE`) 판정, 반차 반영 | Kafka 수신 기반, 휴가 서비스 이벤트 발행 |
| 입사·퇴사 수신 (기본 근무그룹 배정) | Kafka 수신 기반, user-service 이벤트 발행 |
| 급여 집계에 유급휴가 반영 | 휴가 서비스 연동 |
| 관리자 권한 조건 교체 (ADMIN → 직책·직급), `/summary` 권한 제한, 부서장 범위(토큰 `deptId`) | 권한표 |
| 공휴일 조회 API 연동 | 휴가 서비스의 호출 경로(`/api/v1/attn/holidays`)·토큰 전달 수정 |

> 코드 내 관련 위치는 `TODO` 주석으로 표시되어 있음 (IntelliJ TODO 창에서 확인)

## 4. 팀 회의 안건

1. 권한표 (직책·직급별 API 권한)
2. 출처가 있는 결재 문서의 반려 후 재기안 정책 (결재)
3. 결재 취소 연동 방식 (결정 문서 D3)
4. 로컬 개발용 Kafka 호스트 포트 (인프라)
5. user-service `employee.work_group_id`와 근태 `employee_work_group` 중복 정리
6. 연도별 공휴일 등록 방식

## 추천 순서

1. 관리자 근태 현황 → 결재 승인 반영 로직
2. Kafka 준비 후 결재 결과 수신 → 휴가·입사 이벤트 수신
